SECURITY & PRIVACY

Security-aware by design

What this portfolio project does—and deliberately does not claim.

01

Synthetic data only

No real patient or protected health information should be entered. Demo records are fictional.

02

Safer rendering

User-entered values are rendered with DOM text nodes rather than injected as raw HTML.

03

Local storage limitation

Browser localStorage is used for demonstration convenience. It is not appropriate storage for sensitive clinical information.

04

Production roadmap

A real system would require authenticated access, authorization, encrypted transport/storage, audit logging, secure APIs, retention controls, and formal compliance review.

Conceptual architecture

Browser UI→Validation→Local demo store→Analytics

Current version is intentionally client-side. See docs/SECURITY.md for threat-model notes and a production architecture roadmap.
